# 企业微信图片历史记录失效

## 范围与证据

1. 用户报告：企业微信右键复制图片后，再复制其他内容，插件内旧图片无法预览和粘贴。
2. 只读实测：剪贴板同时提供文件 URL、TIFF 与企业微信私有格式。目标为企业微信容器缓存内的 PNG，14751 字节。切换后原文件仍存在且当前诊断进程可读取；SQLite 中目标记录的路径与原文件一致。不能声称文件被删除，也尚未证明 uTools 的具体权限错误。
3. 已确认的脆弱点：采集只保存外部路径；预览和文件粘贴均继续访问同一路径。修复目标是消除此依赖，宿主验收仍待完成。

## BusinessChangeReview

1. Baseline：当前用户故障报告；[图片分类与文件语义](260915/gif-preview.md:5)；[项目规则](../rules/project.md:1)；[知识入口](../knowledge/MEMORY_INDEX.md:1)。
2. Allowed delta：仅对 macOS 企业微信 Images 缓存中的受支持图片，在采集时保存文件副本，记录使用副本路径。优先保留原始字节；单张 PNG 无法读原文件时，尝试将剪贴板 TIFF/图片像素编码为 PNG，此备用路径不保证原文件元数据与编码字节相同。保留原名、来源路径、文件 type、文件复制语义、多文件集合与 GIF 原字节；不对 GIF 或多文件组使用静态像素替代。
3. Preserved invariants：普通文件不复制；混合组不拆分；失败保留原条目并提示；不更改 UI、快捷键、数据库结构、SQLite/JSON 初始化、迁移或重复导入防护。
4. Consumers：采集 → SQLite 或 JSON facade → 图片预览；普通复制、列表粘贴、静默快捷粘贴均沿用已有 file.path 消费链。
5. Test delta：新增回归，不删除或修改旧断言；源文件移除后快照仍可读、字节一致、稳定去重、混合组/失败/上限边界、实际 pbpaste 接线与复制粘贴消费者。
6. Storage：复用 userData 下 original-material，内容 SHA-256 分目录；单轮读取上限 50 MiB。不写用户现有 DB，不批量回填旧记录；重新复制可建立新记录。持久副本当前不随历史清除自动回收，避免影响已复制出的文件及共享记录；磁盘回收是明确限制。

## 实机失败后的补充

1. 已通过窗口看到“图片无法预览”，并核对窗口 URL 指向最新安装包。常见开发者工具快捷键没有打开控制台，尚未取得宿主原始异常；不把文件权限猜测写成已确认根因。
2. 补足单张 PNG 的剪贴板像素备用通路；文件读失败不再直接放弃副本。提示区分读取原文件、读取剪贴板图片、保存副本，并保留 EACCES/ENOSPC 等错误码，不输出文件内容或完整路径。
3. 新增 EACCES + public.tiff 的宿主契约回归、GIF/混合组禁用静态替代、空图与磁盘满失败提示；新增回归、GIF 回归和生产构建均通过。真实 uTools 验收仍待新包安装后完成；当前已安装包不会因为本地 dist 重建而自动更新。
4. 用户更新后反馈没有记录。发现并反证另一个明确入口缺陷：当宿主文件列表为空、格式仅有 public.tiff 时，旧 pbpaste 返回 undefined。先加回归得到失败，再将 TIFF 纳入原生图片格式；getCopyedFiles 抛错也继续读取文本/图片。来源文件路径可用时仍沿用文件语义。新增测试属于补覆盖，不改变原 GIF 断言；实机这一轮是否正好走到该分支仍需验证。
5. TIFF 漏记回归先失败、修复后通过；文件列表异常、GIF、文件副本回归和构建均通过。当前实际运行的是上一版补充包，已通过运行进程打开的 asar 核验；本轮新构建尚未安装，实机记录/预览/粘贴仍未验收。
